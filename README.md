# OCMS

OCMSは、イラストや漫画などの二次元コンテンツの管理に重きを置いた、セルフホスト型のコンテンツマネージャーです。タグ・キャラクターの自動推定、関連コンテンツの表示、重複コンテンツの柔軟な管理を通じて、集めた作品を整理し、見つけやすくします。画像・動画・音声・PDFをブラウザから閲覧できます。

ファイルはOCMSサーバーで暗号化してからストレージへ保存します。ストレージ提供者による保存内容の直接検査・検閲を受けにくくする設計で、E2EEの管理負担を避けながら、クラウドストレージへ平文を預けたくない場合に向いています。復号と解析はOCMSサーバーで行うため、サーバーの運用者を信頼する構成です。

利用者の認証はOIDCにのみ対応しています。導入には、Pocket IDなどのOIDCプロバイダーが必要です。

現在も開発中で、削除したファイルの物理データ回収は未実装です。公開環境で使う場合は、認証・HTTPS・バックアップを別途用意してください。

## できること

- **タグ・キャラクターを自動推定**：画像・動画・PDFからタグとキャラクター情報を推定し、手動でも編集できます。ワードクラウドやグラフから作品を探せます。
- **関連コンテンツをたどる**：共通するキャラクター・タグ、見た目や音の類似性をもとに、選んだ作品に関連するコンテンツを表示します。お気に入りから好みに近い作品を探す「おすすめ」も利用できます。
- **重複コンテンツを柔軟に管理**：完全一致・類似検索で重複候補を探せます。同一内容のファイルは保存データを共有しつつ、登録ごとの名前・タグ・閲覧権限を独立して管理できます。
- **シリーズで連続閲覧**：作品を順番にまとめ、漫画などの画像を一つの作品として扱えます。
- **内容から検索**：ファイル名・タグ・PDF本文・文字起こしのキーワード検索と意味検索に対応します。検索結果から該当ページや再生位置へ移動できます。
- **暗号化して保存**：ファイル本体をサーバー側で暗号化し、閲覧時に復号します。複数ファイルのアップロード、プレビュー、動画・音声の再生、元ファイルのダウンロードを利用できます。

## 起動

Docker Engine、Docker Compose v2以降、Python 3.9以降が必要です。GoとNode.jsはコンテナ内でビルドするため、ホストへのインストールは不要です。

CPUでの推論を含むローカル検証では、Dockerに4 CPU・12 GiBのメモリを割り当てています。これは動作実績であり、すべてのファイルに対する必要量を保証するものではありません。初回のメディア解析ではモデルをダウンロードするため、インターネット接続と数GBの空き領域も必要です。

リポジトリを取得し、ルートディレクトリで実行します。

```sh
git clone https://github.com/usbharu/ocms.git
cd ocms
python3 scripts/dev-init.py
```

起動前に、生成された `.env` の認証設定を次のように変更します。URLと資格情報は自分の環境の値に置き換え、OIDCプロバイダーへコールバックURLを登録してください。この例では `https://media.example.com/auth/callback` です。

```dotenv
AUTH_MODE=oidc
PUBLIC_URL=https://media.example.com
OIDC_ISSUER=https://id.example.com
OIDC_CLIENT_ID=<registered-client-id>
OIDC_CLIENT_SECRET=<registered-client-secret>
```

```sh
docker compose build
docker compose up -d --wait
```

設定した `PUBLIC_URL` を開き、OIDCプロバイダーでログインします。BFFの待ち受けは既定で `127.0.0.1:8080` です。公開URLでHTTPSを受け付け、このアドレスへ転送するリバースプロキシを別途用意してください。

初期化スクリプトが設定する `AUTH_MODE=development` は開発・検証専用です。ローカルで試す場合の手順は[開発環境の起動](docs/development.md#起動)を参照してください。

初期化では `.env` と `secrets/crypto.yaml` を生成し、既存ファイルは上書きしません。**暗号鍵を失うと保存済みファイルを復号できません。** この2ファイルとDB・ストレージのデータを保持し、バックアップを用意してください。

ビルドキャッシュへの書き込みが制限される場合は、[起動時の補足](docs/development.md#起動)を参照してください。

## ファイルを追加して探す

1. 「ライブラリ」を開き、ヘッダー右側からファイルをアップロードします。複数選択でき、既定の上限は1ファイル1 GiBです。
2. 保存後、サムネイル生成や本文抽出などの解析が順に進みます。ファイル詳細から処理状況を確認できます。検索や自動タグへの反映には時間がかかる場合があります。
3. 検索欄へキーワードを入力します。検索欄の「キーワード」から、意味検索・ハイブリッド検索にも切り替えられます。
4. ファイルを選んでプレビューを開きます。タグや名前の編集、お気に入りへの登録、完全一致・類似検索は詳細画面から行えます。

「タグ」「キャラクター」「シリーズ」「お気に入り」「おすすめ」の各画面からも探せます。詳しい操作と設定は[利用ガイド](docs/usage.md)を参照してください。

対応ブラウザでは「アプリをインストール」や「ホーム画面に追加」からPWAとして利用できます。インストールにはHTTPS（ローカル確認はlocalhost）が必要です。オフラインでの閲覧・検索・アップロードには対応していません。

## GHCRの公開イメージ

GitHub Releaseの公開に合わせて、次のイメージをGHCRへ公開します。対応プラットフォームは `linux/amd64` です。

| パッケージ | 用途 |
|---|---|
| [ocms](https://github.com/usbharu/ocms/pkgs/container/ocms) | Web画面とアプリケーションの共通イメージ。各サービスとDB移行に使用 |
| [ocms-runtime](https://github.com/usbharu/ocms/pkgs/container/ocms-runtime) | タグ・キャラクター推定、意味検索、文字起こしと推薦に使用。CPU版とCUDAライブラリ同梱版を提供 |
| [ocms-postgres](https://github.com/usbharu/ocms/pkgs/container/ocms-postgres) | 日本語全文検索・ベクトル検索用の拡張を含むPostgreSQL |

バージョンは[Releases](https://github.com/usbharu/ocms/releases)で確認し、各イメージを同じReleaseにそろえてください。アプリとPostgreSQLにはReleaseタグ、Runtimeには末尾に `-cpu` または `-cuda` を付けたタグを指定します。モデルはイメージに含まれず、初回の推論時に取得します。

通常はCPU版を選んでください。CUDA版も現在の推論はCPUで実行し、CUDA版を選ぶだけではGPU推論は有効になりません。Runtimeの接尾辞なしのタグはCUDA版の別名です。

同梱の `compose.yaml` はローカルビルド用です。公開イメージを使う場合は、各サービスの `image` と `pull_policy` の変更が必要です。各イメージの指定先やタグの規則は[公開イメージの利用手順](docs/development.md#ciとreleaseイメージ)を参照してください。

## DBマイグレーションと更新

既存環境を更新する際は、アプリを停止してDB移行を適用し、成功後に再起動します。`.env`、暗号鍵、既存ボリュームは保持してください。ローカルビルド構成では次を実行します。

```sh
docker compose build
docker compose stop bff worker search transfer catalog
docker compose up -d --wait postgres
docker compose run --rm migrate
docker compose up -d --wait
```

移行に失敗した場合や、旧版でSQLを手動適用したDBを引き継ぐ場合は、[DBの状態確認・復旧手順](docs/development.md#dbマイグレーションと更新)を参照してください。適用済み番号の推測や、dirty状態の自動解除はしないでください。

## 公開環境の認証とデータ管理

利用者向けの認証はOIDCのみです。OCMS独自のパスワード認証は提供していません。ローカル開発用ログインを外部へ公開しないでください。[Pocket IDの設定例](docs/development.md#pocket-id接続)を用意していますが、Pocket IDとの実接続は未検証です。BFFの再起動時には再ログインが必要で、複数BFF間のセッション共有には対応していません。

ファイル削除は論理削除です。削除してもストレージの物理容量は解放されません。DB・ストレージのバックアップ機能も未実装のため、運用側でバックアップと復元の手順を用意してください。暗号鍵の世代更新は[鍵更新と回収](docs/development.md#鍵更新と回収)を参照してください。

停止する場合は次を実行します。名前付きボリュームは保持されます。

```sh
docker compose down
```
